できること
・夫婦それぞれの現在残高・今月の支出を同じ画面に表示
・人を選択して共通の入力欄から支出、返金、追加チャージを登録
・月別の履歴、編集、削除、CSV出力
・毎月1日に一人150ドルを自動加算。未使用分は翌月へ繰り越し
・スマホ・PCで共同編集。表示中は20秒ごと、再表示時にも同期
・金額は1セント単位。残高がマイナスになる支出も記録可能

公開方法はプードル貯金と同じ：GitHub Pages + Supabase
このZIPには接続情報・パスワードは入っていません。
プードル貯金のZIPも接続情報が未設定のため、稼働中の config.js からコピーしてください。
この時点では公開・オンライン接続は未実施です。

1. Supabaseの準備
既存のプードル貯金と同じSupabaseプロジェクトを使用可能です。
SQL Editor → New query に supabase_setup.sql の全文を貼り付け、Run。
既存の farts テーブルやデータは変更しません。
新しいテーブル allowance_settings / allowance_entries と関数を追加します。
SQLの再実行で記録は削除されません。

2. 共有ログイン
プードル貯金と同じログインを使うなら、新しいユーザー作成は不要。
別にする場合は Authentication → Users で共有アカウントを1つ作成し、
メール確認済み（Auto Confirm User）にしてください。
夫婦の端末では必ず同じメール・パスワードを使用してください。
別々のアカウントでは別のデータになります。

3. config.js
SUPABASE_URL：稼働中のプードル貯金の同名項目からコピー。
SUPABASE_ANON_KEY：同じくanon public key（または公開用publishable key）をコピー。
LOGIN_EMAIL：共有アカウントのメール。空欄なら画面で入力。
パスワードや service_role key / secret key は書かないでください。

4. GitHubで新しいリポジトリを作成
プードル貯金を上書きしないよう、新しく our-allowance 等のリポジトリを作成。
GitHub Pagesの利用条件に合う公開設定にしてください。
ZIPを展開して、中の全ファイルと icons フォルダをリポジトリ直下にアップロード。
ZIPそのものや、外側のフォルダをアップロードしないでください。
index.html と config.js が直下に並ぶ状態にし、Commit changes。

5. GitHub Pagesを有効にする
リポジトリ Settings → Pages → Build and deployment
Source：Deploy from a branch
Branch：main、フォルダ：/(root) → Save
デプロイ成功後、Pages画面に表示されたURLを開く。
例：https://あなたのGitHub名.github.io/our-allowance/
（このURLは例です。実際のURLはGitHubで確認してください。）

6. 夫婦の端末で使う
同じ公開URLを開き、同じメール・パスワードでログイン。
iPhoneはSafariの共有 → ホーム画面に追加。
片方で登録し、もう片方の「更新」で同じ履歴が表示されることを確認。

毎月のチャージの仕組み
・初めてログインしてデータ取得に成功した月を開始月にします。
・開始月にも二人へ各150ドルを付与します（日割りしません）。
・以後、米国東部時間 America/New_York の毎月1日0時で加算。
・現在残高＝開始月から当月までの月数×150＋返金/追加－支出。
・サーバー時刻から毎回計算するため、未起動の月も漏れずに反映。
・自動加算は履歴上の計算行であり、テーブルに毎月の行を挿入する方式ではありません。
・定期実行の設定は不要です。チャージ額・開始月は通常の画面から変更できません。
・月初に開いたままでも次の同期（通常20秒以内）で反映されます。
・開始前から持っていたお金は「返金・追加チャージ」で登録できます。
・一時帰国などで端末の時差が変わっても、判定は米国東部時間に固定です。

編集と共有
同時に違う記録を追加しても、別々の行として保存。
同じ記録を同時編集/削除した場合はバージョンを照合し、先の変更を保護。
通信失敗では保存済みと表示しません。更新して履歴を確認してください。
オフラインでの記録は非対応です。
ログイン情報は端末に保持されます。共有端末ではログアウトしてください。
GitHub Pagesの画面自体は公開されますが、記録はログインとRLSで保護します。
記録はログインしたアカウントのものだけ読み書きできます。

お試し画面
URL末尾に ?demo=1 を付けると接続設定なしでも画面を試せます。
お試しデータは一時的で、再読み込みすると初期状態に戻ります。
お試し画面での記録は本番に保存されません。
